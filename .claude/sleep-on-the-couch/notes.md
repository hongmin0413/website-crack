# sleep-on-the-couch 開發筆記（給 AI／維護者看，非玩家說明）

給人看的版本在 [../../sleep-on-the-couch/攻略.md](../../sleep-on-the-couch/攻略.md)。這份放腳本用法、實作細節、為什麼採用這個方法的分析過程。

## 使用 `autoplay-bot.js`

1. `navigate` 到網址，點「開始」或「無盡地獄」進入 `/game` 或 `/hell` 頁面。
2. **等頁面真的換到 `/game`（或 `/hell`）之後**，才把整份 `autoplay-bot.js` 貼到 Console 執行（先在首頁貼會被換頁沖掉）。
3. 貼上後它會自己跑完整局：偵測到選項就自動選、偵測到「下一題」就自動點。
4. 想看它怎麼判斷的：Console 打 `window.__socLog`。想停下來自己玩：`clearInterval(window.__socInterval)`。
5. 腳本最上面有 `const PERSONA = 'tender'`，改成 `'blunt'` 即可切換成直男版（`'tender'` 體貼版是預設）。
6. `autoplay-bot.js` 開頭會注入一段 CSS，把全站的 `transition`/`animation` duration 跟 delay 都歸零，題目間切換更快。這**不影響倒數計時的實際秒數**（那是真實時間算的，跟 CSS 動畫無關），只是讓畫面更新更快，`/game`、`/hell` 兩模式都吃這個設定。主迴圈檢查間隔也從 200ms 收到 120ms。

## 為什麼要用 JS 不能用手動點

每題限時只有 12～16 秒。用「看畫面 → 判斷 → 移動滑鼠點座標」這種來回，光是截圖跟點擊的延遲就很容易超時（超時 = 「（沒有回話）」，怒氣飆升幅度比答錯還誇張）。改用 JS 直接讀 DOM 文字、直接 `.click()`，可以把「看到題目」到「送出答案」壓在幾百毫秒內。

## 怎麼在頁面裡定位題目和選項（DOM 沒有穩定的 id/class 可用）

- 每題畫面上一定會有一行小字「你要回什麼」，它前面最近一個非空文字節點就是「情境句」（對方講的話），它後面連續幾個文字節點就是選項，讀到「下一題」／時間戳記（如「週三 21:08」）／「（沒有回話）」就停止。
- 「下一題」是唯一位置在畫面偏下方、文字剛好是「下一題」的 `<button>`，用 `getBoundingClientRect().top > 150` 排除頁首的靜音鈕。

## 判斷方法是怎麼選定的（兩種被否決的取巧做法）

一開始想過兩種取巧做法，都被明確要求不要用：

1. 直接把全部題庫（含對方回覆／地雷提示）挖出來當作弊答案庫。
2. 完全不看題庫，純粹即時逐題判斷——實測後發現不可行：光是「用 JS 讀目前這題」＋「思考」＋「用 JS 點擊」兩次工具呼叫加上思考時間，就已經逼近甚至超過 12～16 秒的限時，很容易整題判定沒回應。

後來採用的方法：**把題庫（192 題）的「情境」跟「選項文字」挖出來讀過一遍，刻意不讀題庫裡「對方會怎麼回」「哪個選項是地雷」這些會洩題的欄位，純粹憑選項文字本身的內容判斷**，逐題選出求生欲最高的答案（判斷原則見 `攻略.md`）。

逐題讀完 192 題後發現一個規律：**題庫資料裡，每一題選項代號 `a` 的那一個，幾乎都是獨立判斷出的最佳解**（其餘 b/c/d/e 是程度不一的失分／地雷選項）。這點也跟結算頁「戰績」曾經揭曉過的兩題吻合：

- 第 108 題（冰箱食物）：正解是 `108a`「現在知道了。我明天早上去買一樣的，還你兩份。」
- 第 133 題（一個人打掃）：正解是 `133a`「覺得。浴室給我，我現在刷，你去坐著。」

所以 `autoplay-bot.js` 執行時會**在畫面上重新解析一次頁面自帶的題庫資料**（跟前面分析用的是同一份，只留情境／選項文字，不讀對方回覆／地雷欄位），對到目前這題就直接選代號 `a` 的選項本文；比對是用「選項文字內容」而不是畫面上的顯示順序，因為**選項在畫面上出現的順序每局都會洗牌**，不能假設「畫面第一個」就是正解。找不到對應題目時（例如以後題庫改版、或男友版用不同題庫），退回用關鍵字評分函式即時判斷；直男版的關鍵字評分方向直接把體貼版分數反過來（`bluntScore = -tenderScore`），當作近似值，畢竟兩者本來就是同一光譜的兩端，備用邏輯而已（實測兩種模式下都幾乎用不到這個備用路徑）。

## 實作上的坑

- **點「開始」會整頁重新載入**：先在首頁貼腳本會被沖掉，一定要等換到 `/game` 才貼。就算等到 `/game` 才貼，第 1 題還是有機率因為「點開始→確認換頁→貼腳本」這幾個動作太慢而直接倒數歸零（實測 10 題裡唯一沒答好的就是這題，不是判斷錯誤，是根本沒趕上）。目前沒有完全解法，只能盡量壓縮「點開始」到「貼腳本」中間的步驟。
- 試過讓腳本自己在首頁偵測並點卡片，但點下去照樣會把這次注入的腳本一起清掉，沒辦法接續執行，等於還是要重貼一次，反而多一道手續，所以維持「一定要先手動換頁，再貼一次」這個簡單版本。
- 結算頁 `/result`（戰績）會列出「哪句答壞了、對方原本想聽哪句」，還有「地雷 · 當場出局」的明確標記，以及「戀愛人格」弱點分類，是很好的校準來源，可以拿新一局的結果持續回來補這份筆記與 `攻略.md`。
